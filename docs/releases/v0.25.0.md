# v0.25.0 — 插件系统迁移 Cordis 范式（对齐 DSH）

## 架构级变更：插件系统全新范式

Stardust 插件系统从「渲染进程 React + 运行时 esbuild 编译」彻底迁移为 **DSH/Cordis 范式**：

- **插件运行时 = @deepseek-ai/cordis**（DSH 同款），主进程 rootCtx
- **插件形态 = Cordis 插件**（`name/inject/provide/apply(ctx)`）
- **工具在主进程执行**（`ctx.tools.register` + `defineTool`），不再 IPC 往返渲染进程
- **Host/Client 半端分离**（对齐 DSH）：
  - Host 半端（src/index.ts）：AI 工具、服务注册 —— 主进程 Cordis 运行
  - Client 半端（src/client.ts(x)）：页面挂载 —— 渲染进程加载
- **移除运行时 esbuild 编译**：插件预编译为自包含 `lib/index.js`（零外部依赖、零 spawn）
- **宿主服务注入**（ctx.provide）：sidecar / fs / sandbox / mcp / supabase / defineTool
- **主进程自动加载**已安装插件（不依赖渲染进程状态）

## 插件开发新范式

```ts
// src/index.ts — Host 半端
export const name = 'my-plugin'
export const inject = ['tools', 'supabase']
export function apply(ctx) {
  const defineTool = ctx.get('defineTool')
  ctx.tools.register(defineTool({
    name: 'my_tool',
    description: '我的工具',
    parameters: { q: { type: 'string', required: true, description: '关键词' } },
    output: { schema: { type: 'string' }, render: (_a, v) => [{ type: 'text', text: v }] },
    execute: async (args) => { /* 主进程执行，可 ctx.get('supabase') */ },
  }))
}
```

构建：`node scripts/build-plugin.mjs 插件目录`（产物 lib/index.js + lib/client.js）
